# GTMS v1.0 — 인터넷 배포 안내

## Render에 공개 웹주소 만들기

이 저장소는 Render Blueprint 배포용 `render.yaml`을 포함합니다. 배포가 완료되면 `https://서비스이름.onrender.com` 형태의 주소가 발급됩니다.

1. Render 대시보드에서 **New → Blueprint**를 선택합니다.
2. GitHub 계정에서 `ranjintj1-dot/GTMS-Web` 저장소를 선택합니다.
3. 설정 파일(`render.yaml`)을 확인하고 **Apply**를 선택합니다.
4. 배포 로그에서 서비스 상태가 **Live**가 될 때까지 확인합니다.
5. 발급된 `.onrender.com` 주소를 열어 GTMS 화면이 표시되는지 확인합니다.
6. `https://서비스주소/api/health`를 열어 `{"status":"ok"}`가 반환되는지도 확인합니다.

## 접속 방식

- 기본 설정은 **로그인 없이 바로 접속**하는 방식입니다.
- 공개 URL을 아는 사람은 누구나 접속할 수 있습니다. 특정 사용자만 보도록 제한하는 비공개 인증 기능은 기본적으로 켜져 있지 않습니다.
- 서버는 `GTMS_USER`와 `GTMS_PASSWORD` 두 환경변수가 모두 설정된 경우에만 HTTP Basic Authentication을 적용합니다. 로그인 없는 접속을 유지하려면 두 변수를 Render에 설정하지 마세요.
- 항공편 정보나 운항 관련 KML/Excel 파일 등 민감한 자료는 공개 웹서비스에서 취급하지 마세요.

## 현재 시스템 범위

- Leaflet 기반 2D 세계지도, CesiumJS 기반 3D 지구본
- 항공편/출발지/도착지/순항고도 입력
- KML 및 Excel/CSV 항적 입력
- NOAA SIGMET 및 PIREP 조회 프록시
- Open-Meteo ECMWF IFS 바람 자료 기반 실험적 벡터 윈드시어 스크리닝
- 5분 주기 자료 갱신

## 운영상 주의

위험등급은 검증된 EDR 난기류 예측값이 아니라 바람 벡터 차이를 이용한 실험적 스크리닝 지표입니다. 공식 항공기상 예보, 운항승인, 디스패치 판단, 조종사 판단을 대체하지 않습니다. 실제 항공사 운용 전에는 기상자료 품질, 알고리즘 검증, 접근통제, 감사로그, 장애대응, SMS/변경관리 검토가 필요합니다.
